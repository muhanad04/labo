# Product

## Platform

web

## Stack

Delegated: the user explicitly authorized stack changes and implementation. React, TypeScript, Vite, SVG/HTML, Zustand, and Zod; Vitest and Playwright for verification. See docs/STACK.md for package checks and deferred choices.

## Users

University students, initially the project's author and university friends who cannot afford access to a commercial virtual lab.

## Product Purpose

An independent electrical-engineering teaching bench: construct circuits, understand connections, calculate trustworthy readings, and record investigations. Success means completing and reopening a meaningful experiment without paid simulator access.

## Operating Context

Public reference research is in docs/RESEARCH.md and docs/SOURCES.md. No vendor code/assets are available for reuse. The user requested an original, polished, expandable alternative and efficient context for subsequent coding sessions.

## Capabilities and Constraints

Implemented: ideal DC and single-frequency RMS AC linear circuits, RLC/phased sources, basic balanced/unbalanced three-phase networks, parameter/frequency investigations, recorded measurements and bounded named local projects. Transformers, machines and true transients remain future work. No accounts, paid backend, vendor-format compatibility or proprietary courseware. Educational only, not physical wiring guidance. Exact model/format limits: docs/MODELS.md and docs/MIGRATIONS.md.

Delegated working assumptions: desktop/laptop-first, responsive reading/control layout on phones, English initially, local-first storage. The specific university course, additional languages, production hosting, and project license remain undecided. These are assumptions, not confirmed user needs.

## Brand Commitments

Name: labo. Independent identity, no affiliation with Festo/LabVolt. User delegated visual and technical decisions after requesting polish and depth.

Explicit user correction: a professional, utilitarian laboratory application, with the reference's functional directness rather than a modern promotional dashboard. No slogans, inspirational/coaching copy, rounded tiles, floating cards, large brand treatments or gratuitous empty-state writing in the workspace. Use compact toolbars, plain equipment lists, numeric instruments and terse status. Keep technical help/model limitations available on demand. This preference overrides the initial calibration-workbench styling.

**Approved design baseline — frozen by the user:** preserve this utilitarian design language and operating philosophy. Polish may improve legibility, alignment, control consistency, accessibility and interaction precision. New capabilities must inherit the same language. Changes to the visual identity, core workspace grammar or promotional/coaching stance require explicit user approval; do not start a new aesthetic exploration by default.

## Evidence on Hand

Public source register, written research, independent analytical fixtures, residual/conservation checks and browser workflows. No customer claims, external-engine/hardware equivalence, runtime-performance benchmarks, photographs or vendor implementation models.

## Product Principles

- Physics before decorative realism; invalid results never masquerade as measurements.
- Make connectivity and assumptions inspectable.
- A small complete experiment beats a large nonfunctional catalog.
- Separate experiment editing, numerical analysis, and presentation.
- Preserve local work and document exactly what is supported.

## Accessibility & Inclusion

Proposed engineering standard: keyboard-operable core workflow, labelled controls, visible focus, reduced-motion support, and no reliance on wire color alone. No formal accessibility conformance claimed.
