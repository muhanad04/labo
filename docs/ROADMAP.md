# Roadmap

Current handoff: [NOW.md](NOW.md). Physical limits: [MODELS.md](MODELS.md). Larger intent: [VISION.md](VISION.md). No placeholder equipment or fake measurements.

## Frozen design baseline

User-approved crude/utilitarian desktop laboratory: gray chrome, compact native commands, flat instruments, numerical displays and terse status. Polish/accessibility and new tools inherit it; no aesthetic reboot, promotional copy or default coaching.

## Completed foundations

- [x] Independent public research/provenance, locked static React/TS/Vite stack, pure domain/solver seam and concise agent handoff.
- [x] Validated ideal DC MNA, actual meters/switch/reference, analytical examples, diagnostics, residual and power checks.
- [x] Wiring/highlighting, drag/nudge/zoom, parameter inspection, immutable snapshots/CSV and bounded history.
- [x] Native menus/equipment filter/sort, panel controls and docked data; rejected dashboard styling remains regression-tested.

## Completed expansion — 2026-10-17

1. [x] **Editor precision:** manual lead waypoints, keyboard/numeric routes, endpoint reconnection, group select/move/duplicate/delete, optional grid snapping, atomic undo.
2. [x] **Instrumentation:** explicit endpoints/probe connections, units/polarity, adjustable display-only precision; phases/P/Q/S/PF when meaningful.
3. [x] **Investigations:** bounded parameter/frequency sweeps, invalid-point diagnostics, real sampled plot/table, cursor/previous comparison, immutable basis, cancellation, stale detection, restore and CSV.
4. [x] **Linear AC/three-phase:** RMS phasor MNA, RLC/phased sources, RL/wye presets, balanced/unbalanced wye/delta and floating-neutral analytical tests. Not transient or machine simulation.
5. [x] **Durability:** strict v1/v2 readers and v2 writes, untouched legacy key, guarded previous autosave and eight named local projects with export/confirmed actions.
6. [x] **Verification:** 56 unit/state tests; 14 workflows each in Chromium and Firefox; desktop/phone review and scoped axe scan. No dependencies added by expansion.

## Next milestone — transformer depth

- [ ] Design explicit primary/secondary terminal identity and polarity/ratio conventions; preserve all existing two-terminal files. Document migration before schema changes.
- [ ] Implement an ideal transformer model with ratio, signed winding voltage/current and energy conservation. Test open/load/short constraints and ideal-network failure cases independently.
- [ ] Add one original instrument/experiment using the existing utilitarian grammar. Then model explicit losses/regulation only when required, not arbitrary efficiency sliders.
- [ ] Confirm actual university experiment priorities before choosing subsequent machine models. Do not claim transformers already work.

## Following physics milestones

- [ ] One chosen machine experiment: generic documented parameters, back EMF/torque/speed, shaft/load/inertia and energy-balance proof. Steady-state and dynamic behavior must be distinguished.
- [ ] True transients/time integration and scope only with a validated formulation, timestep/error controls and independent reference cases. Never label reconstructed phasors as startup waveforms.
- [ ] Harmonics, tolerances/faults and thermal/protection behavior only as supported models, not catalog art.

## Practical operation / pilot gates

- [ ] Real student course/language/device feedback and larger-text/assistive-tech testing.
- [ ] WebKit and real touch/keyboard/screen-reader validation; Chromium/Firefox automation is not complete conformance evidence.
- [ ] Automatic obstacle routing/collision-aware placement and shared-topology schematic view, only if student usage justifies them.
- [ ] More conditioning/numerical stress cases and external reference-engine comparisons. Current analytical fixtures are not commercial-equivalence proof.
- [ ] Persist sweep runs/project attachments if needed; currently runs are session-only plus CSV. IndexedDB/offline startup require their own preservation/rollback plan.
- [ ] License decision/transitive asset review, then repository/CI/static host selection. No remote, release, deployment or PWA is configured.
- [ ] Optional guided exercises belong in a separate opt-in mode, never default workspace coaching.

Workers, large plotting packages, backend/auth/cloud and plugin frameworks must earn their complexity from measured workload or a concrete second implementation.
